# Maite 設計メモ

実装より先に決めておかないと後戻りが高くつくことだけを書く。
「何を作るか」ではなく「**なぜその判断か**」を残す。

---

## 1. 芯

**戦闘力の出どころを作業ログにする。**

レベルもステータスもスキルも、Claude Code の使い方から生える。だから対戦は「開発スタイル同士の戦い」になる。職人（Bash 中心）と探索者（調べもの中心）が戦う。育成のための操作が存在しないので、ユーザーは普段どおり仕事をするだけでいい。

ここが他のデスクトップマスコットと違う唯一の点。ここを薄めたら作る意味がない。

### 作業 → スキルの対応（Phase 1 で実装）

| 作業ログ上のシグナル | 生えるもの | |
|---|---|---|
| `comebacks`（失敗したツールを直後に成功させた回数） | 「不屈」HP1 で耐える | ✅ |
| テストを通した回数 | 「検証の一閃」確定命中 | **保留**（下記） |
| `Task`（サブエージェント）の使用 | 「召喚」分身が殴る | ✅ |
| `WebSearch` / `WebFetch` の比率 | 「先読み」先制 | ✅ |
| `compacts`（compact をまたいだ長時間セッション） | 「記憶術」デバフ解除 | ✅ |
| `nightOwl`（0〜5 時の作業比率） | 「夜目」夜間補正 | ✅ |

`traits` は Phase 0 の時点で全部数え始めている。Phase 1 でスキルに変換するだけで済む。

**スキルは state に保存しない**（`src/core/skills.js`）。traits から毎回導出する純関数にしてあるので、閾値を変えても `STATE_VERSION` を上げずに済み、events.jsonl から自動的に付き直る。

**「検証の一閃」だけが出せない。** events.jsonl に入っているのはツール名と成否だけで、その `Bash` が何のコマンドだったかは残していない（§2b 原則 1）。今のログからは原理的に導けない。出すなら hook 側で「テストらしいコマンドか」を真偽値に落として 1 フィールド増やすことになる ── 中身は保存しないままだが、**hook が引数を覗く範囲は広がる**。プライバシーの線に触るので §9 に送った。

## 2. プライバシー ── どこまで緩めたか

**2026-08-14 に原則を 1 つ緩めた。** 「機械の外に一切出ない」は、複数の場所で作業しても 1 匹が育つことと両立しない。合流させる場所が要るため。

緩めたのは**送るかどうか**だけで、**何を送るか**は変えていない。出るのは `events.jsonl` の 1 行そのまま ── イベント種別・ツール名・成否・ハッシュ。プロンプト本文もパスも元から保存していないので、送る内容も増えていない。送り先は本人の Cloudflare アカウントだけで、既定はオフのまま。

「テレメトリなし」→「**自分の置き場にだけ、数値だけ、設定したときだけ**」。

以下は緩める前から変わっていない原則。

## 2b. プライバシーの原則

この手のツールで刺さっているのは「**テレメトリなし。機械の外に一切出ない**」という一点。対戦とスマホ表示はこれを構造的に壊しにいく。ここを雑にやると、いちばんのファンから真っ先に叩かれる。

**原則**

1. **記録は派生値のみ。** プロンプト本文・ツール引数・パス・実行結果を保存しない。`cwd` と `session_id` はハッシュにして持つ（同一性判定にしか使わないので平文は不要）
2. **外部送信は既定オフ。** opt-in するまで通信コードが動かない
3. **送るものを全部見せる。** 設定画面に、実際に送信される JSON をそのまま生で表示する

**Phase 2 で送信する全量（これ以上は増やさない）**

```json
{
  "id": "a3f9c1...",
  "name": "ぽち",
  "level": 14,
  "class": "artisan",
  "stats": { "atk": 42, "def": 31, "spd": 28 },
  "skills": ["verify_slash", "recall"],
  "seed": 88213
}
```

`id` はランダム UUID。アカウントもメールもパスワードも無い。

## 3. チート ── ランキングを作らないことで解く

`state.json` はユーザーの手元にある。Lv999 は誰でも作れる。署名しても鍵がクライアントにあるので無意味。

**対策：順位表を作らない。**

順位表があるからチートに旨味が出る。1v1 の遭遇と、自分だけが見る戦績に留めれば、盛る動機がほぼ消える。サーバー側は「1 日に増えうる EXP の上限」だけ見て、逸脱している個体をマッチング母集団から静かに外す程度でいい（弾いたことを本人に通知もしない ── いたちごっこの入口になる）。

日次 EXP キャップ（`DAILY_EXP_CAP`）は成長ペースの調整であると同時に、この sanity check の基準線でもある。

**400 → 1,500 に上げた（実測して分かったこと）。** 400 は「作業を始めて 1.7 時間」で埋まっていて、よく使う日ほど捨てる割合が増えていた ── 1 日 800 イベントで 74%、1,600 イベントで 87%。つまり **Claude Code を一番使っている人の相棒が、一番早く育つのをやめていた**。これは §1 の「戦闘力の出どころは作業ログ」と正面から食い違う。1,500 は「よく働いた 1 日がちょうど収まる」高さで、これを超えるのは人が 1 日に叩ける量を明らかに越えているので、基準線としてはまだ効く。

イベント単価（`EXP_TABLE`）ではなく上限を動かしたのは、単価だけ上げても上限が同じなら**埋まるのが早まるだけ**だから。

### 「1 日」をどこで切るか

上限の区切りと夜更かし（0〜5 時）の判定は、**人間の 1 日**に乗っている。どちらも機械のローカル時刻で見ていたが、**Cloudflare Worker のローカル時刻は UTC** なので PC とサーバーで別の日を見ていた。

実際に起きたこと：日本時間の 9〜14 時（昼間）が Worker からは 0〜5 時に見えるので、**昼に働くほど「夜目」が育っていた**。判定が裏返っていた。今日の一戦も、日本の 0:00〜9:00 のあいだは PC とスマホで別の日の試合が出ていた。

**オフセットを外から渡せるようにした**（`src/core/clock.js`）。既定（`null`）は機械のローカル時刻なので PC 側は変わらず、Worker だけ `AIPET_TZ_OFFSET`（分。日本なら 540）で切り方を合わせる。**イベントにフィールドを足していない** ── オフセットは弱い位置情報なので、記録に混ぜずに設定側で持つ（§2b）。旅行しても追従させたいなら hook 側に載せる話になるが、そこは踏み込まない。

## 4. コールドスタート ── ゴースト戦と、正直な表示

初期は対戦相手がいない。

- **リアルタイム同期はしない。** 相手のスナップショットを 1 体ダウンロードして、クライアント側で決定論的に自動解決する（seed = 両者 ID + 日付）。相手はオフラインでいい。サーバーは戦闘計算をしないので激安で済む
- 母数が足りない時期は生成ボットで埋める。ただし画面に「**まだ対戦相手が少ないため、練習相手と戦っています**」と出す。ここを黙ると信用が飛ぶ

## 5. 放置要素 ── 報酬を 2 系統に割る

「使っていないのに強くなる」と、Claude Code の使用実態と切れてしまう。かといって放置報酬が無いと、放置ゲーの気持ちよさ（次に開いたときの土産）が出ない。割る。

| | 得られるもの | 条件 |
|---|---|---|
| **実作業** | EXP・レベル・スキル・系統 | Claude Code を実際に使う |
| **放置（オフライン探索）** | 素材・コスメ・装備・お土産 | 起動していない間、勝手に探索に出る |

強さのインフレは起きず、それでいて「留守中これ拾ってきたで」は出る。

**実装（`src/core/expedition.js`）も保存しない。** 拾ったものは (種 + 留守に入った時刻 + 留守の長さ) から毎回導出する。だから state に持ち物の欄が増えず、`STATE_VERSION` も上がらない ── スキルや戦闘と同じ扱い。種に「いまの時刻」を混ぜないのが要点で、混ぜると**開いたまま眺めているだけで中身が入れ替わる**。

30 分未満は出さない（ちょっと離席しただけ）。12 時間で頭打ち（1 週間ぶりに開いて大量に出ても嘘くさい）。帰って作業を始めると `lastEventAt` が動くので土産は消える ── 「留守番の報告は帰ってすぐ聞く」で足りるうちは、これでいい。**貯めて持ち物にするかどうかは §9。**

**やらないこと**

- **放置で弱る・死ぬ**。罪悪感ドリブンは嫌われる。世話される側ではなく、**見守ってくれる側**に置く
- 戦闘に操作を要求する。オーバーレイが操作を求めた瞬間、邪魔なアプリになる。戦闘は完全オートで、ログを眺めるだけ
- 通知でしゃべる。黙っていられることが常駐アプリの品格

## 5b. 実績 ── バッジであって、ミッションではない

デイリーミッションを作らないと決めている（§3, §5）以上、実績も**それを狙って作業を変えるもの**であってはいけない。ここを踏み外すと「普段どおり仕事をするだけでいい」が即座に壊れる。

**線引き**

- 条件は**普段どおり働いていれば勝手に満たされる量**にする。「今日中に」「7 日連続で」は作らない
- **期限も取り逃がしも無い。** 遅れて達成しても同じように付く
- **見せ方も後追い。** 「あと 3 回で達成」を出した瞬間、それは目標になる（未獲得の実績は条件を薄く並べるだけで、進捗バーは出さない）

**これだけは state に保存する。** スキルと戦闘は導出のままにしてあるが、実績には「**獲得した瞬間**」が要る ── 現在の traits からは「いつ超えたか」を復元できない。ただし刻むのは events.jsonl を畳む途中の時刻なので、畳み直せば同じ時刻が再現される（`applyEvent` の純粋性は変わらない）。ここが「保存に倒してよかった」数少ない場所。

獲った瞬間は**画面の中の吹き出しだけ**で伝える。OS の通知は出さない（§5）。

## 5c. しぐさ ── いちばん長く見ている画面は「何も起きていないオーバーレイ」

**この判断は作ってから変えた。** 戦闘を実装して眺めてみると、実際に見たいのは「戦闘ログを読むこと」ではなく「**育っているかどうかを横目で確かめること**」だった。ログは読むのに集中が要る（＝仕事の邪魔になる）が、しぐさは視界の端で足りる。

- **画面に出ている間、ときどき勝手に動く。** 伸び・きょろきょろ・あくび・首かしげ・寝返りなど。何も起きていない時間が長いほど、ここが効く
- **気分でできることが変わる。** 許可待ち（`calling`）のときは何もしない ── 返事を待っている子がのんきに伸びをしたら、見ている側が気づけない。寝ているあいだは跳ねない
- **気分ごとの「らしさ」を持たせる。** 考えている時は首をひねって止まり（`ponder`）、作業中は打鍵のリズムで小刻みに動き（`typing`）、寝ているあいだは浮かぶ（`dream`）。どの気分でも同じしぐさが出ると、気分そのものが意味を失う。ほかに、画面のこちら側をのぞきこむ（`peek`）と、たまにくしゃみ（`sneeze`）
- **体だけ動かしても伝わらない。** のぞきこむときは瞳を下げ、考えるときは上を見て、くしゃみは一瞬目をつぶる。体の動きと目の動きが揃って初めて「近づいてきた」「考えている」に見える
- **戦闘は「読むもの」から「たまに見かけるもの」に降ろした。** 開いたときにその日の一戦を 1 回だけ再生する。勝った日は最後に跳ね、負けた日はよろける ── 数字を読まなくても結果が分かる。ログ自体はスマホ側に残してあるので、読みたい日は読める
- **レベルアップと実績も動きで出す。** 数字が増えたことより、跳ねたことのほうが目に入る

この変更で **§7 の判断基準がずれた**。「戦闘ログが面白いかどうかで Phase 2 に進むか決める」としていたが、戦闘がログではなくしぐさになった以上、Phase 2（他ユーザーとのゴースト戦）の値打ちは「知らない誰かの個体が出てくること」のほうにある。判断はまだ出していない。

## 5d. 戦闘 ── 相手の強さは見せない

**相手のレベルを出さない。** 出した瞬間「あと何レベルで勝てる」が計算できてしまい、負けた日はその時点で終わる。分からないから、明日また見る。代わりに手応え（「まるで歯が立たなかった」「あと一歩だった」）だけ返す。系統は相性に効くので見せる。

相手は **自分のレベルの -15% 〜 +22% の範囲で広く振る**（Lv20 なら -3 〜 +4）。強さを見せない前提があって初めて、この幅が「今日は誰に当たるか分からない」になる。**幅を割合にしているのは、ステータスがレベルに比例して伸びるから** ── 「+5」の重みは Lv20 と Lv100 で別物で、固定幅にしていた頃は Lv20 で +8 に勝率 0%、Lv50 で +8 に 78% と、育つほどレベル差が意味を失っていた。

**ちゃんとやれば報われる／一発逆転は何度も起きない**

- **番狂わせ補正**は格下側だけに掛かる。差は段数ではなく**比**で見て（`gap / (自分のレベル + 6)`）、埋めるのはその 8 割ぶん。全部埋めると差そのものが消えて運ゲーになる
- **会心は 1 戦に 1 度だけ。** ただし格下ほど**出やすく、重い** ── 倍率を固定にしていた頃は、8 発のうち 1 発が少し重いだけで総ダメージが 15% しか増えず、格上に勝てるのは 1〜2% だった。一撃で HP の半分を持っていける重さにして初めて番狂わせが起きる
- 実測（Lv20・技あり）：同格 51%、+3 で 29%、+5 で 24%、+8 で 16%。**格上には基本負ける。でもゼロではない**
- この形は**どのレベル帯でも同じ**。-20% で 78%、同格で 50%、+20% で 25%、+50% で 5% 前後（`node scripts/balance.mjs levels`）

**系統の配点は「合計」ではなく「勝率」で揃える。** 以前はどの系統も重みの合計を 2.0 に揃えて「総量は同じ、形が違う」としていたが、実測すると同レベル総当たりで**職人 73% / 学者 25%** だった。ダメージは atk に二重に効く（威力そのものと、防御を抜ける割合の両方）ので、**atk 1 点は def 1 点の約 2.5 倍の値打ちがある** ── 同じ点数を配っても、防御に振れた系統は最初から負けている。形（3 つの比）は触らずに、勝率が五分に揃う倍率を解いて焼き直した。結果、系統平均は 49〜53%（ブレ幅 49pt → 4〜6pt）で、レベルを変えても揺れない。

**相性**は 5 系統を一本の輪にした（§7 では Phase 3 に置いていたが、戦闘を眺めるものにした時点で前倒しした）。有利な側に攻撃のバフ、不利な側に守りのデバフ。攻撃 +15% / 守り -12% で試したら同レベルの勝率が 80% 対 20% になったので、いまは有利セルの平均が 74% ── **系統は働き方の結果で選べない**ので、その日の相性で勝負がほぼ決まるのは違う。

**技は 1 つで勝敗を決めない。** 練習相手への勝率で測って、★3 でも +21pt（不屈）／+18pt（召喚）／+8pt（先読み）に収めてある。不屈は「★1 でいきなり確実に 1 回耐える」をやめ、段位で**耐えられる確率**（45% / 75% / 100%）が上がる形にした ── 最初に生える技だけで 38pt 動くと、後から生える技が誤差になる。

**数字を動かしたら `node scripts/balance.mjs` を通す。** 上の値は全部そこで出る実測で、勘で置いた数字はひとつも無い。

## 6. スマホ ── 読み取り専用、サーバーは対戦と共用

スマホでオーバーレイは無理。だが**見るだけ**なら放置要素と相性が非常にいい（電車で「うちの子、留守中に何拾ってきたかな」を開く、が放置ゲーの本体）。

- スマホ側は**読み取り専用のダッシュボード**。レベル・系統・見た目、放置探索の成果、直近の戦績ログ。操作は一切なし
- URL を叩くだけなので **PWA** でホーム画面に置ける。アプリストア不要
- 認証は**推測不能 URL 1 本**（`/p/<ランダム32文字>`）。ログインもアカウントも作らない

### 段階を 2 つに割った

「スマホで見たい」に対して、いきなりサーバーを立てるのは重い。手前に 1 段置いた。

| | 見られる場所 | 要るもの | 状態 |
|---|---|---|---|
| **LAN 配信** | 同じ Wi-Fi の中だけ | 何も要らない | ✅ 実装済み |
| **外部ホスト** | どこからでも | Cloudflare アカウント | ✅ 実装済み |

LAN 配信は Electron 側で `http.createServer` を 1 本立てるだけ。アカウントも契約も無しで、その日のうちにスマホで見られる。認証が無いので、**同じ Wi-Fi にいる人には見える**（出るのはレベルとカウンタの数値だけだが、公共回線では立てない）。

重要なのは、**このとき書いた HTML と `/api/state` がそのまま外部ホスト版で使える**こと。`src/mobile/` は fetch 先が変わるだけで、載せ替えの手間が出ない。だから「あとで作り直し」にならない。

**重要**：このスマホ用サーバーと Phase 2 のマッチング用サーバーは**同じ 1 本**で済む。どちらも「スナップショットを置いて読む」だけ。つまりスマホ対応で作る物が増えるのではなく、**サーバーを作る時期が前倒しになるだけ**。

## 6b. 課金 ── 技術は買えない。時間は買える

**売るのは「遡れる範囲」であって、EXP の量ではない。**

`~/.claude/projects/**/*.jsonl` に、Claude Code は全セッションの記録をローカルに残している。hook を入れる前の作業がそこに全部あるので、畳めば「本当に働いた通りのレベル」から始められる。

| | 取り込める範囲 |
|---|---|
| 無料 | 直近 30 日 |
| **1 ドル 1 本** | **さらに 30 日ぶん**（重ねて買える） |
| 引き換え券（`all`） | 全期間 ── 自分用と、詫びに配るぶん |

**1 本で全部を開けない。** 「一度払えば全部」だと、買う理由が一生に一度しか来ない ── 30 日ずつなら、もっと前まで遡りたくなったときに、その都度また 1 ドルを払う理由ができる。しかも**払って増えるのは「見える範囲」だけ**なので、何本重ねても下の線は 1 ミリも動かない。

**「1 ドルで 30 日ぶんの経験値が手に入る」と言ってもいい。** ただしそれは、**その 30 日に本当にやった作業ぶんの経験値**であって、金額に応じて配られる EXP ではない。1 ヶ月まるごと休んでいた人が 1 ドル払っても、増えるのは 0 EXP ── そこがこの売り方の全部。

**同じログを入れたら同じレベルが出る。ルールは全員同じで、公開して困るところが 1 つも無い。** 課金した人は本当に強いが、それは長く働いていたからで、係数が優遇されているからではない ── §1（戦闘力の出どころは作業ログ）が 1 ミリも崩れない。

**やらないと決めたこと：同じログから、払った人だけ多く EXP が出る作り。** 黙ってやれば両側に嘘をつくことになるし、`events.jsonl` も `state.json` も手元にあるので誰か 1 人が diff を取れば終わる。刺さっている層は、まさにそれをやる層でもある。

引きの強さは変わらない（「課金したら強い状態で出る」は同じ）。変わるのは、それが本当かどうかだけ。

取り込みの実装は `src/core/transcripts.js`。**記録には本文も引数もパスも入っているが、取り出すのは hook が書くのと同じ派生値だけ**（§2b 原則 1）。ここが緩むと、取り込み機能からプライバシーの主張が崩れる ── テストで縛ってある。

**鍵の実装は `src/core/license.js`。** Ed25519 の署名を検証するだけで、変わるのは `reachFor()` が返す日数ひとつ。ここが返す値以外に課金で変わるものは無い、をテストで縛ってある。**同じ鍵を 2 回貼っても日数は増えない**（id ごとに数える）。

**どこまで守れるかは、正直に見積もってある。** 署名なので「それらしい文字列」は通らないし、鍵が 1 本漏れても他人の鍵は作れない。**ソースを書き換えれば外せる** ── それは分かっていて、それでいい。`state.json` も `events.jsonl` も手元にあるので、手元で完結する検証は必ず外せるし、外せない形にするにはサーバーで畳むしかなく、それは「自分の PC の中だけで完結する」という前提のほうを捨てることになる。狙いは**うっかり共有される鍵を止めること**であって、本気で外す人を止めることではない。

**催促しない。** 範囲の外に何件残っているかは `scripts/import.mjs` を自分で叩いたときに 1 行だけ出す。オーバーレイにもスマホにも出さないし、期限も割引も出さない ── 焦らせて買わせる作りは、そもそもこの鍵では成立しない（外せるので）。買う理由は「遡れると嬉しい」だけで足りる。

### 6c. もう 1 本 ── スキン

遡れる範囲は重ねて買えるが、それでも**遡り切ってしまえば、そこで終わり**。並べて置くつもりなのはスキンで、条件は 2 つ。

- **数字に一切触らない。** §1（戦闘力の出どころは作業ログ）を崩さない
- **別のキャラにしない。** この子は自分の働き方から出てきた個体なので、着せ替えで別物になったら愛着の土台が消える。色・質感・小物のレイヤーに留めて、**顔つきは型のまま**（§8c）

順番にも意味がある。鍵は入れて 3 日目くらいがいちばん効く（「入れた瞬間 Lv34 で出てくる」）。スキンは逆で、**4 ヶ月見てきた子にしか価値が出ない** ── 密度が高いほど売れる商品なので、先に密度を作る。

## 7. フェーズ

| | 中身 | サーバー |
|---|---|---|
| **Phase 0** ✅ | hooks + state + デスクトップオーバーレイ | 不要 |
| **Phase 1a** ✅ | スマホビュー（LAN 配信） | 不要 |
| **Phase 1b** ✅ | どこで作業しても 1 匹が育つ + 外出先からスマホで見る | Cloudflare Workers ✅ |
| **Phase 1** ✅ | スキル生成 ✅ + オートバトル（ボット相手）✅ + 放置探索 ✅ | 追加ゼロ |
| **Phase 2** | 他ユーザーとゴースト戦 | 追加ゼロ |
| **Phase 3** | 系統相性、装備、週替わりイベント | 追加ゼロ |

**Phase 1 でボット相手の戦闘まで作ってから Phase 2 に行く。** 戦闘が面白いかどうかはサーバー無しで分かる。面白くなければ Phase 2 をやらない判断ができる。

作ってみた結果、**戦闘は「読むログ」ではなく「たまに見かけるしぐさ」に降りた**（§5c）。判断の基準もそれに合わせて動いている ── Phase 2 の値打ちは戦闘の中身ではなく、知らない誰かの個体が画面に出てくることのほうにある。

## 8. 技術的な決定と理由

| 決定 | 理由 |
|---|---|
| **Electron**（Tauri ではなく） | 最初に検証したいのは「毎日起動したくなるか」で、10MB か 150MB かはそこに効かない。詰まりどころの情報量を優先した。後から差し替えは効く |
| **hook は append のみ** | hook は Claude Code に同期でブロックして呼ばれる。重い処理を置くと本体が待たされる |
| **hook は必ず exit 0** | 非 0 は Claude Code の動作をブロックする。おまけが本体を止めてはいけない |
| **成長ロジックは純関数** | `events.jsonl` を畳み込めば state をいつでも再構築できる。ルール変更後の移行が「作り直す」で済む |
| **レベル上限 999** | 上限まで働き続けても Lv100 に 124 日、Lv999 に 19 年。天井の意味は「**どこまでなら表示も戦闘も壊れないと保証したか**」で、そこまでは数字が溢れないことをテストで縛ってある。曲線を緩めて本当に届く高さにするかどうかは別の判断（§9） |
| **レベルは逆関数で求める** | `applyEvent` はイベント 1 件ごとに呼ばれる。1 ずつ数え上げる実装だと、上限付近では 1 件畳むのに 1 万回まわる |
| **cursor でオフセット管理** | ログは追記のみなので未読分だけ読めばいい。ファイルが縮んでいたら state ごと作り直す（半端に混ざるより安全） |
| **500ms ポーリング**（fs.watch ではなく） | `fs.watch` はプラットフォーム差が大きい。`stat` 1 回のポーリングは実質ゼロコストで、挙動が全 OS で同じ |
| **`focusable: false`** | フォーカスを奪った瞬間に「邪魔なアプリ」になる |
| **renderer は成長ルールを持たない** | 表示と判定が二重定義になると必ずズレる。`core/growth.js` を唯一の真実にする |
| **サーバーも同じ `growth.js` を使う** | Worker は依存ゼロの純関数をそのまま import する。合流点で別のルールが走ると、PC とスマホで数字が食い違う |
| **畳むのは受信時** | 読むたびに全イベントを畳み直すと、増えたときに Worker の CPU 時間に収まらない。生ログは残すので、ルール変更時は次の受信で自動的に畳み直される |
| **イベントに ID を持たせる** | 送信失敗時は丸ごと再送する作りなので、重複が届くのが前提。ID があれば二重に数えずに済む |
| **送信は別プロセス** | hook 自身がネットワークを待つと Claude Code が待たされる。`Stop` などの区切りで detached に投げ、結果を待たない |
| **送信の cursor は表示用と別** | 送信が詰まっても表示は進む。逆も同じ。片方の失敗がもう片方を止めない |

## 8b. 名前 ── 働き方が、そのまま名前になる

**名前は 1 つだけ。型（§8c）から出た職が、そのままこの子の名前になる。**

前は 3 つ並んでいた ── 種から決まる現実の職（大工・灯台守）、系統（学者）、型から出た
二つ名（魔道書士）。全部それらしい肩書きなので、**どれがこの子の名前なのか読めなかった**。
一本化すると 2 つ効く：

- **名前を見れば、どう働いているかが分かる**（「導師 Lv14」）
- **働き方が変われば、名前のほうが変わる** ── 放っておくと知らない間に変わっている

引き換えに、種から決まる「その子だけの名前」は無くなった。同じ働き方の人は同じ名前に
なる ── 自分だけの名前が欲しい人は付け替える（`node scripts/name.mjs さくら`）。

型が決まるまでは**見習い**。**起動時に名前は訊かない**（§1）── 入力欄を出した瞬間、
起動直後に「まず名前を決めてください」という手続きが生まれる。付けたい人だけが後から付ける。

**付け替えた名前は state に置かない。** state は events.jsonl から作り直せるもので、
ログから導けない値を混ぜると畳み直すたびに消える。手元では設定
（`~/.aipet/config.json`）に、サーバーでは KV の別キー（`name:<key>`）に置く。
hook は送信のたびにこの名前を一緒に投げるので、スマホにも同じ名前が出る。

## 8c. 型 ── 読まずに当てる

**「AI を使っているあなた自身」が、そのままキャラクターの名前になる。** ただし
**本文は一文字も読まない**（§2b）。読んでいるのは今までどおり「どの道具を何割・
何時に・1 つの指示で何回動いたか」だけで、プロンプトもツールの引数も見ていない。

**読まずに当てるから面白い。** 中身を覗いて当てても、それはただの盗み見になる。
黙って裏でやるのはもっと悪い ── 自分の PC で、`state.json` を開けば見えて、
コードも手元にあるのだから**必ずバレる**。見つかった瞬間に、それまで良かったところまで
疑わしくなる。「本文は読んでいません。読んでいないのに、こうなります」と
画面に出しておくほうが、隠すより驚きが大きい。

4 つの軸（`src/core/persona.js`）。閾値は実測（`scripts/usage.mjs`）から置いた。

| 軸 | 左 | 右 | 何を見ているか |
|---|---|---|---|
| reach | 籠る | 出て行く | 調べもの（WebSearch / MCP）と Task の割合 |
| hand | 動かす | 組み立てる | 実行（Bash）と、読み書き（Read / Edit）の比 |
| grip | 刻む | 委ねる | 1 つの指示で動くツールの数 |
| run | 散らす | 走り切る | 1 セッションでどれだけ手を動かすか |

**5 軸目は「リズム」で、二つ名の後ろに付く**（「炉守（凪）」/「炉守（波）」）。上の 4 つが
「何をしているか」なのに対して、ここだけ**時間の形**を見る ── 働いた日ごとの EXP の
ばらつき（`state.days`）で、同じ型でも走り方が違う。

| 軸 | 左 | 右 | 何を見ているか |
|---|---|---|---|
| rhythm | 凪 — 毎日おなじ調子で積む | 波 — 乗った日に一気に持っていく | 働いた日ごとの量の揃い方（ここ 2 週間） |

**休んだ日は数えない。** 入れると、土日を休む人が全員「波」になる。見るのは
「働いた日のあいだで、量が揃っているか」のほう。**4 軸より遅れて付く**のも意図
── 5 日ぶん働かないと揃っているかを言えないので、揃うのを待つと 1 週間なにも出ない。

**出すのは二つ名。借りてきた 4 文字は出さない。** 測り方の骨格（4 軸 ＋ 揺れ）は
よく知られた性格分類から借りているが、そのまま `INTJ-T` と出した瞬間、**借りてきた
診断の結果**に見える。ここで出したいのは診断結果ではなく、その人の使い方から生えた
一匹なので、画面に出るのは 32 通り（16 × 凪 / 波）の二つ名と、その根拠にした軸だけ。

| | 動かす（工房・野） | 組み立てる（書庫・空） |
|---|---|---|
| **籠る × 刻む × 走り切る** | 鍛冶師 | 魔道書士 |
| **籠る × 刻む × 散らす** | 罠師 | 呪紋師 |
| **籠る × 委ねる × 走り切る** | 錬金術師 | 結界師 |
| **籠る × 委ねる × 散らす** | 傀儡師 | 幻術師 |
| **出て行く × 刻む × 走り切る** | 竜騎士 | 占星術師 |
| **出て行く × 刻む × 散らす** | 狩人 | 吟遊詩人 |
| **出て行く × 委ねる × 走り切る** | 獣使い | 導師 |
| **出て行く × 委ねる × 散らす** | 傭兵 | 精霊使い |

**これがこの子の名前になる**（§8b）。割り当ては軸の意味そのまま ── 籠って手を動かす人は
工房、籠って組み立てる人は書庫、外に出て体で確かめる人は野、外を見て絵を描く人は空と海。
**系統（職人・学者…）と技（召喚・不屈…）とは語を重ねない** ── 同じ語が別の意味で
二度出ると、画面の壊れに見える。

**軸は「累計」ではなく「直近 2 週間の窓」で見る。** 累計で決めていた頃は、続けるほど
分母が育って**一度決まった名前が二度と動かなかった**（1 年使った人は、以降どう働き方を
変えても同じ名前のまま）。窓にしたことで、**打ち方・指示の出し方・活動の傾向が変われば、
1〜2 週間かけて名前のほうが変わる** ── 実測では、読んで刻む働き方から叩いて大きく投げる
働き方に変えて 8 日目に「魔道書士 → 鍛冶師」、11 日目に「錬金術師」へ。

窓だけだと境目に乗った日から毎朝ひっくり返るので、**境目の ±0.06 にいる間はこれまでの
自分に倒す**。「知らない間に変わっていた」はいいが、「毎朝ちがう名前」は別物。

**変わった瞬間だけは state に刻む**（`state.jobs`）。型そのものは導出だが、
「いつ変わったか」は現在の state から復元できない（実績と同じ理由）。畳み直せば同じ時刻が出る
── スマホには「8月6日から。それまでは 魔道書士 だった」と出て、オーバーレイは
変わった瞬間に「魔道書士 → 鍛冶師」と一度だけ言う。

**なった職は実績にも残る。** `state.jobs` は直近ぶんしか持たないので、渡り歩いた道は
実績のほう（`job:<key>`）に貯まる ── 実績パネルに「なった職 4 ／ 魔道書士 6月17日 ／
鍛冶師 7月17日 ／ 錬金術師 7月20日 ／ 獣使い 8月4日」と、通ってきた順に並ぶ。

**まだなっていない職は一覧に出さない。** 出した瞬間に「16 個集める」チェックリストに
なり、集めるために働き方を変える話になる ── それはデイリーミッションと同じ（§5b）。
実績の分母（`13 / 26`）にも入れていないので、埋まらない枠が増えることもない。
ここにあるのは「そういえば あの頃は罠師だった」だけ。

**3 つ目の軸は、一度作り直している。** 最初は「つまずいてから、その場で立て直した
割合」で測ろうとしたが、実測するとほとんどの人が 0.8 を超えた（同じ道具はすぐまた
使うので、10 分の窓に勝手に収まる）。**動かない値を性格とは呼べない**ので、
「1 回の指示で、どれだけ勝手に走らせるか」に差し替えた ── こちらは人によって桁で違う。

守っていること：

- **保存しない。** 技（§1）と同じで traits と系統ベクトルからの導出。だから閾値を
  いじっても `STATE_VERSION` を上げずに済むし、働き方が変われば型が後から付いてくる
- **母数が足りないうちは断定しない。** 3 回叩いただけで「あなたはこういう人です」と
  言われたら、当たっていても嘘くさい。4 軸とも母数が足りて初めて名乗る
- **根拠を必ず横に出す。** 「あなたは○○型です」だけだと占いになる。何を見てそう
  言っているかが見えていれば、外れていても「そう見えるわな」で終われる
- **一度決めた型を固定しない。** 累積の比率なので、使うほど分母が増えて自然に
  落ち着く。「決めたら変えない」を入れると、働き方を変えたときに型が付いてこない

**型は見た目に出る。** 4 軸ぶんのクラス（`p-in` / `p-build` …）が `#stage` に付いて、
瞳の大きさ・口元・顔の広さ・目の開きが変わる。リズムは `r-calm` / `r-wave` で
**息づかいの速さ**になる（凪 はゆったり、波 はせかせか）。しぐさの出やすさも型で変わる
（`src/shared/gestures.js` の `PERSONA_WEIGHTS`）── 「うちの子はよく画面を
のぞきこむ」が、そのまま「外に出て行くほうの人だから」になっているのが、この機能の値打ち。

## 9. 未決

> **決着したもの**
>
> - **拾ったものを貯めるか** → **貯めない。** 装備は `src/core/dungeon.js` で導出する。到達階層は traits から出る計算値、どの階で何を拾ったかは「個体の種 + 階」から毎回引き直す。**貯めなくても「拾って着けて強くなる」が成立する**ので、state に持ち物の欄は増えなかった（`STATE_VERSION` も据え置き）。留守番の土産（`expedition.js`）は従来どおり読みもののままで、強さには関わらない

- **プロジェクトごとに別の個体にするか** ── `p`（cwd ハッシュ）は既に記録しているので後から分岐できる。「うちのリポの子」は拡散の燃料になるが、1 匹に集約したほうが育つ実感は強い
- **タスクトレイ** ── まだ未実装（`Ctrl+C` で終了）。常用するなら必須
- **KV のログの上限** ── 生ログを 1 キーに追記し続けている。KV の値は 25MB までで、1 イベント約 90 バイトなので 27 万件ほどで頭打ちになる。そこまで行く前に、古いぶんを畳んだスナップショットに置き換える処理が要る
- **「検証の一閃」を出すために hook を 1 歩踏み込ませるか** ── ツール引数を覗いて「テストらしいコマンドか」の真偽値だけを記録すれば §1 の対応表が埋まる。保存するのは派生値のままだが、hook が見る範囲は広がる。踏み込まないなら、この技は表から落とすことになる
- **レベル曲線を緩めるか** ── 日次上限を 1,500 に上げたことで「総量」は直った（Lv50 まで 36 日、Lv100 まで 124 日）。**直っていないのは「1 レベル上がる間隔が広がり続ける」ほう。** 上限いっぱいで働いても Lv10 は 0.4 日おき、Lv50 は 1.3 日おき、Lv100 は 2.2 日おきになる。上限を上げるのは全部を定数倍するだけなので、この広がりには効かない ── 効くのは指数のほう（`k=1.75` → `1.45` にすると Lv100 でも 1.7 日おきに収まる）。ただし**変えると全員のレベルが動く**ので、実際の伸び方を何ヶ月か見てから決めたい
- **戦績を残すか** ── いまの戦闘は state から毎回導出していて、どこにも保存していない（そのぶん `STATE_VERSION` を上げずに済んでいる）。「直近の戦績ログ」（§6）を出すなら保存が要るが、state に戦績が増えると、ルール変更のたびに畳み直せる性質が薄れる
- **スプライト** ── 現在は SVG のプレースホルダ。ベース + 装備 + オーラのレイヤー合成にすれば、絵を数百枚描かずに組み合わせで数百パターン出せる。ここをケチると系統分岐が活きない
